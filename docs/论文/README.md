## 2. 各章要点与"不能写成什么"

### 第 1 章 绪论

- 1.1 背景与意义：仿真测试在 MIL/SIL 环节的位置，以及"平台自身的迭代效率"
  如何以乘数效应影响算法产出。
- 1.2 研究现状：三档平台（3D 高保真 / 交通流 / 轻量算法环境）、场景生成、
  闭环验证与可复现性。
- 1.3 能力边界：用 `docs/横向对比.md` 的表 1、表 2 做定量对照，指出"保真度—
  迭代效率—硬件成本"三角。
- 1.4 本文工作与贡献：四条，逐条对应到第 4、5 章的可验证结果。
- 1.5 组织结构。

**不能写成**：文献综述式的平台罗列。评审最反感"CARLA 支持 X，SUMO 支持 Y"
的清单；每一段都要落到"因此本课题要解决什么"。

### 第 2 章 相关技术与理论基础

- 2.1 车辆运动学模型（自行车模型、曲率与转角关系、适用边界）。
- 2.2 跟驰与换道模型（IDM、MOBIL），以及为什么本平台只取 4 类模板。
- 2.3 路径跟踪控制（Stanley 律、曲率前馈）。
- 2.4 激光雷达点云与聚类（轮廓采样、DBSCAN、PCA 框拟合）。
- 2.5 仿真确定性与时间轴回溯（快照 + 重推演）。

**不能写成**：教科书抄写。每节结尾要有一句"本平台采用了什么、放弃了什么、
为什么"。

### 第 3 章 需求分析与总体设计

- 3.1 需求：功能性（闭环、回放、注障、生成）与非功能性（帧率、时延、
  冷启动、可回归）。
- 3.2 四层架构与依赖规则（L3 零 Qt 的强制手段）。
- 3.3 五个端口与装配根。
- 3.4 线程模型与单写多读快照。
- 3.5 协议设计（TCP 状态/指令 + UDP 点云分片）。
- 3.6 时间轴与回溯语义（无损回看 vs 分支截断）。

**不能写成**：类图堆砌。每一条设计决策都要给出"不这样做的代价"，架构文档
里已有大量这类对照，直接改写即可。

### 第 4 章 关键模块实现

- 4.1 物理推进与确定性（固定步长、浮点可复现）。
- 4.2 点云生成与"雷达欺骗"注入通路（只进点云、不进真值）。
- 4.3 时间轴缓冲与快照策略（1500 帧 / 25 帧间隔、内存占用）。
- 4.4 渲染管线（算绘分离、扫描线写点云、十万点预算）。
- 4.5 算法进程（感知/决策/控制、时延测量口径）。
- 4.6 场景生成（NL → JSON、schema 校验、模板回退）。
- 4.7 交互与 HUD（右键注障、帧级拖拽、三态判据）。

**不能写成**：代码说明。以"问题—方案—代价"组织，关键处给数据（如十万点
P99 5.99 ms、回溯 0.009 ms）。

### 第 5 章 实验与结果分析

- 5.1 实验环境与口径（含"时延测量对负载敏感"的警示，实验报告 §2.1）。
- 5.2 E1 渲染性能；5.3 E2 通信时延；5.4 E3 回溯一致性；
  5.5 E4 闭环精度；5.6 E5 场景生成有效性。
- 5.7 横向对比（CARLA/SUMO/PreScan/highway-env/CommonRoad）。
- 5.8 讨论：哪条指标没达标、为什么、影响多大。

**不能写成**：只报达标项。E2 的十万点重载、E5 的 24% 回退都必须写进去，
并给出归因与后续方案——这是评审判断"作者是否真的做过"的关键。

### 第 6 章 总结与展望

- 6.1 工作总结（对应 1.4 的四条贡献，逐条回到数据）。
- 6.2 不足：感知保真度、行为库规模、弯道参与者推进方式、Python 侧开销。
- 6.3 展望：向量化/下沉 C++、行为模板扩展、与 CARLA 的联合仿真。

## 4. 写作纪律

1. **数字只从三份实测文档取**（实验报告 / 性能压测报告 / 横向对比），
   不临时拍；口径不一致时以实验报告为准，并在脚注说明。
2. **不写没有数据支撑的程度副词**（"显著提升""大幅优化"），改成差值或倍数。
3. **每个"首次/创新"必须能被第 5 章的数据或第 4 章的代码指认**，否则删掉。
